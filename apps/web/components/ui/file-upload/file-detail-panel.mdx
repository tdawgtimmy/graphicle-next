# FileDetailPanel

Combines `FileSelectionItem`, `FileErrorAlert`, and a consumer-supplied detail
view into a component that can be used for file review. Loading, error, and
no-selection states are handled by the panel from each file's `status`. If a
file has been successfully loaded, the panel renders its `children` below a
heading with the filename and delete button.

<Primary />

## Composing the success state

`children` is only rendered while the selected file has `status: "success"`.
This allows the panel to be customized based on the call site/by the owning
component. For example,

```tsx
function ImportStep() {
  const [files, setFiles] = React.useState<UploadFile[]>(/* ... */);
  const [selectedId, setSelectedId] = React.useState<string>();
  const selected = files.find((f) => f.id === selectedId);

  return (
    <FileDetailPanel
      files={files}
      selectedFileId={selectedId}
      onSelectFile={setSelectedId}
      onCancelFile={cancelUpload}
      onDeleteFile={removeFile}
    >
      {selected?.status === "success" && (
        <AttributeTableDetail key={selected.id} file={selected} />
      )}
    </FileDetailPanel>
  );
}
```

- **Key `children` by the file's ID.** Selecting a different file re-renders
  the same slot rather than remounting it, so local state in your detail view
  leaks between files. `key={selected.id}` fixes it.
- **`w-full`/`h-full` is not necessary.** The slot is a CSS Grid cell that
  stretches by default. You content does need to survive anything from 640px up.
- **The filename and delete button come from the panel.** Your content sits
  `1.5rem` below them.
- **Guard on `selected?.status === "success"` anyway.** The panel checks too,
  but the guard narrows `selected` for TypeScript and you need that narrowing to
  read the file's data.

## `UploadFile` and immutability

`files` takes `UploadFile[]`, the same ttype your store or upload hook should
hold, so the same objects can go to `FileDetailPanel` and to any other
file-aware UI.

Treat `UploadFile` as immutable. A status transition (`"loading"` →
`"success"`) needs a new object; mutate in place and a memoized row holding the
old reference will never re-render.
